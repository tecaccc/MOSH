## 实现详情

### 日历「今天」定位跨天失效（BUG1）

**现象**：今天是 25 号，日历月视图却把 24 号高亮为「今天」；今日视图/首页的
日期文案、今日到期过滤同样停留在昨天。

**根因**：应用是托盘常驻进程（关闭可配置为后台驻留），但 5 个视图都在
**模块顶层**固化了启动那一刻的时间——

```ts
const today = todayOnly();   // MonthView / TimeGrid / AgendaView / TodayView / HomeView
const now = new Date();      // TodayView / HomeView（问候、日期行、逾期判定）
```

模块只在应用启动时加载一次，跨午夜后这些值全部停留在启动日；日历 store 的
`cursor` 也只在启动时初始化为当天。昨天启动的应用，今天永远「今天 = 24 号」。

**修复**（新增 `src/lib/use-today.ts`，全视图替换）：

- 新增 `useToday()` hook：分钟对齐轮询 + `visibilitychange`/`focus` 即时校准
  （覆盖托盘唤醒、系统休眠唤醒），跨天返回新 date-only；同值 `setState` 时
  React 跳过重渲染，轮询无渲染开销。
- **月/周(共用 TimeGrid)/议程视图**：模块级 `today` → `useToday()`，跨午夜后
  「今天」高亮自动滚动到新日期。
- **CalendarPane 日切光标跟随**：store 新增 `initDay`（启动日）。日切后若光标
  仍停在旧「今天」或启动日（= 用户没翻页）→ 自动 `goToday()` 定位到新今天；
  用户已翻页离开则不打扰。同时覆盖「24 号启动、25 号才首次打开日历」的场景。
- **今日视图**：`today` → `useToday()`；`now` 改为组件内分钟级时钟（对齐分钟
  边界，与首页时钟同款）。日期行/问候随日切滚动，「今日到期/已逾期/已完成」
  过滤与 DuePill「今天 · HH:mm」逾期着色随分钟刷新（此前 `now` 固化，逾期
  着色一整天都不更新）；事件加载 effect 增加 `today` 依赖，跨天自动重载窗口。
- **首页**：`today/tomorrow` 改为响应式；问候/大日期/星期行/月历脚注复用已有
  分钟级 `clockNow`；日程窗口（今天起 30 天）跨天自动重载；月历 mini-grid
  「今天」高亮、分组头「今天/明天」标签随之滚动。

### 顺带：星期标签 UTC 解析错位

排查中发现 `CalendarPane`（日模式标题）、`TimeGrid`（日头部）、`AgendaView`
（分组头）用 `new Date("2026-08-25")` 取星期——date-only 字符串按 **UTC 午夜**
解析，负 UTC 时区（美洲）下 `getDay()` 会落到前一天、星期标错。统一改用
`calendar-grid` 的 `parseDateOnly`（本地构造；已从私有改为导出）。

### Windows7 适配（评估后不修复）

用户机器报 `mosh.exe - 无法找到入口：GetSystemTimePreciseAsFileTime`。实测
定位（交叉编译 hello-world + objdump 导入表比对）：

- Rust **1.77.2** 构建的二进制：仅 `GetSystemTimeAsFileTime` 等 Win7 可用导入；
- Rust **1.97**（当前工具链）构建：静态导入 `GetSystemTimePreciseAsFileTime`
  （Win8+）、`WaitOnAddress`/`WakeByAddress*`（Win8+，含
  `api-ms-win-core-synch-l1-2-0.dll`）、`ProcessPrng`（bcryptprimitives.dll，
  Win10+），MSVC 与 GNU 两条 std 均如此——Rust 1.78 起 std 移除了 Win7
  delayload 兼容层，**静态导入在加载期即失败**，无运行时兜底。

要恢复 Win7 可运行，需：Rust ≤ 1.77.2 旧工具链 + `lettre`/`chacha20` 等
edition2024 依赖整链降级 + CI 双工具链维护 + 锁死 lockfile 不再升级——与
「跟进上游安全更新」长期冲突，且 WebView2 本身在 Win7 已停止支持。结论：
**不做适配**，Win7 用户无法运行属预期。

### AI 修改待办：新增 `update_todo` 内置工具

**背景**：手动编辑待办已完备（TodoEditor + `update_record` IPC），但 AI 工具
只有 `create_todo` / `set_todo_status` / `add_subtask`——日程有 `update_event`
而待办无对应修改工具，用户让 AI 改待办标题/截止/优先级/标签时无工具可用。

**实现**：

- `service.rs`：新增 `update_todo(db, id, patch)`——kind=todo 校验（event id
  拒绝）+ 合并 patch 后标题非空校验（与创建同约束）+ `updated_at`/`revision`
  维护，与 `update_event` 同构。
- `agent/tools.rs`：注册 `update_todo`（id 必填，title/description/due_at/
  priority/tags 只传要改的字段）。**null 语义**：`description`/`due_at` 显式
  传 `null` → 清除该字段（两者在待办上皆可空）；缺省 → 不改。`arg_str` 会
  丢弃空串，故空串同缺省，模型想清除应传 null（工具描述已言明）。
- `agent/runner.rs`：系统提示词第 5 条补充待办修改守则。
- 前端 `state/agent.ts`：`MUTATING_TOOLS` 加 `update_todo`（落库后即时刷新
  各视图）、`TOOL_LABELS` 加「修改待办」（工具卡片标题）。审批 Write 模式
  下自动需批准（不在 `READ_ONLY_TOOLS` 白名单）。

**顺带**：修复新版 clippy（1.97）两个既有 lint 报错，恢复
`cargo clippy -p mosh-core --all-targets -- -D warnings` 绿灯：
`notify.rs` 测试 `assert_eq!(x, true)` → `assert!`；`merge.rs` 测试
`&[remote.clone()]` → `std::slice::from_ref(&remote)`。

**验证**：`cargo test -p mosh-core` 129 通过（新增 3 测：工具层改字段/null 清
截止/非待办与幽灵 id 拒绝、服务层校验）；clippy -D warnings 绿；`tsc --noEmit` 绿。
