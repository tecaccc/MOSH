## 实现详情

### 一、侧栏隐藏/展开开关（标题栏最左，带动画）

**交互**（用户返工后定稿：开关固定在标题栏最左侧，隐藏/展开同一位置）：

- 标题栏最左侧（x=0）钉一个 36px 开关按钮：**绝对定位浮层，不占网格列**——
  tb-left 始终与下方侧栏同步 248↔0 宽度动画，竖线全程零错位；
- 图标为标准「侧边栏开关」形（圆角矩形 + 左侧 1/4 处竖线，VS Code/Lucide
  `panel-left` 同族）；展开时竖线左侧小块淡填充示意侧栏挂载，折叠时淡出只剩轮廓；
- 全局快捷键 **Ctrl/⌘+B** 同效（按钮 title 提示）；
- 折叠状态经 localStorage（`mosh:sidebar-collapsed`）持久化，重启保持。

**动画方案**（不依赖 grid 轨道动画，兼容各 webview）：

- 布局保持 grid，标题栏为 `auto 1fr auto`（开关为绝对定位浮层不占列，
  tb-left 列 auto 跟随），应用区首列 auto 跟随侧栏元素：`.sidebar { min-width/max-width: 248px }`（≤900px 时
  64px）同步 transition 到 0 —— 网格每帧重解轨道，`1fr` 主区平滑补位；
- 标题栏左段（`.tb-left`）与侧栏同一状态、同一节奏（0.28s
  `cubic-bezier(0.4,0,0.2,1)`）收放；折叠后由开关按钮自身补上与主区的分隔线
  （边线颜色过渡），展开时与侧栏色带无缝连成一体；
- 侧栏内容层 `.inner` 固定内容宽（收起时不挤压、仅被裁切）：折叠时 0.12s 快速淡出，
  展开时延迟 0.12s 再 0.2s 淡入（内容随面板打开渐显，不生硬）；
- 开关图标旋转与宽度动画同节奏（0.28s 同缓动）；`prefers-reduced-motion` 下全部瞬时。

**状态**：`useAppStore` 新增 `sidebarCollapsed` + `toggleSidebar()`（UI 偏好不入
后端 config），TitleBar/Sidebar 按 selector 订阅。

### 三、AI 聊天两侧留白（对话列居中 + 输入框同宽对齐）

**问题**：会话侧栏移除后聊天主区全宽，用户/AI 气泡仅 24px 贴边，视觉拥挤。

**方案**（`ChatPanel.module.css`，对话列变量 `--chat-col: 780px`、`--chat-gutter: 24px`）：

- 消息区 `.msgs` 两侧 padding 改为 `max(24px, (100% - 780px) / 2)`：宽窗口时
  对话内容收到 780px 居中，两侧大留白；窄窗口（≤828px）回落 24px；
- 输入区 `.composer`、错误条 `.err`、审批栏 `.approval` 均改
  `width: min(100% - 48px, 780px)` + 水平居中：与消息列同一计算基准（.main 宽度），
  任意窗口宽度下严格对齐，不受滚动条占位影响；
- 气泡 max-width 72% 不变（相对收窄后的列宽，宽屏下阅读宽度回归合理）；
  顶栏仍全宽（标题/模型/新会话），空态引导卡本就居中。

### 验证（聊天留白）

- `npm run check` / `npm run build` 通过；
- 对齐口径：消息列宽 = W - 2·max(24,(W-780)/2) = min(W-48, 780) = composer 宽度，
  数学上恒等，所有窗口宽度一致对齐。

### 五、聊天 hero 模式（空会话输入框居中，发送后滑落底部）

**效果**（参考 Codex 桌面版）：空会话时问候标题 + 输入框垂直居中于舞台；
发首条消息后输入框丝滑滑落到底部，消息从顶部展开；「+ 新会话」清空后反向滑回居中。

**实现**（`.stage` 舞台结构，flex-grow 插值动画，无 JS 动画库）：

- 舞台内固定渲染：`msgs`（消息区）→ `spacer` → 错误条/审批栏/`hero`（问候块）/
  `composer`（输入框组）→ `spacer`——**输入框组在两个 spacer 之间**；
- hero 态（`data-hero=true`，messages 为空）：两个 spacer 各 flex-grow:1，
  把「问候+输入框」整组夹在垂直居中；msgs flex-grow:0（padding 归零）收为 0 高；
- 发送瞬间：`send()` 在 IPC 前同步写入用户消息 → `data-hero` 立即翻转为 false，
  spacers flex-grow 1→0、msgs 0→1 同步 0.45s `cubic-bezier(0.4,0,0.2,1)` 插值——
  **输入框组从居中滑落到底部**，消息区同步展开；
- 问候块 `max-height + opacity` 同步折叠淡出；新会话反向滑回居中；
- 过渡期间首条消息不被裁切：滚到底逻辑在 `transitionend` 后补一次（容器展开
  完成时 scrollTop 落在最终态）；
- `prefers-reduced-motion` 下全部瞬时；旧 `.empty` 空态块移除（并入 hero）。

**返工注记**：共返工两次——① 首版把 composer 放在两个 spacer 之后，spacer 只夹住
了问候文案，输入框始终钉在底部（居中与滑落均未生效）；修复为把 err/approval/
hero/composer 整组移入两个 spacer 之间，并对齐滚动时机。② 结构修复后 CSS 编辑
因同批另一处改动匹配失败而整次原子回滚，舞台样式（.stage/.spacer/.hero）实际
未落盘，导致输入框顶到最上方、hero 文字无样式且常驻；补齐后用 grep 核对全部
类名落盘再验收。（教训：多块原子编辑失败时必须逐项核对实际落盘结果）

### 验证（hero 模式）

- `npm run check` / `npm run build` 通过；flex-grow 为可插值数值，Chromium webview
  原生支持过渡，无需 FLIP/JS 动画。
