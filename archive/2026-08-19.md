## 实现详情

### MCP 打开应用不显示（BUG）

- 根因：技能/MCP 列表只存在 `useAgentStore`（`loadChatTools()`），而它的唯一入口是
  `init()`——挂在 `ChatPanel` 挂载时（`currentView === "agent"`）。应用默认视图是
  「首页」，打开应用直接进「设置 → AI 工具」时 store 尚未初始化，MCP 列表/计数
  （含 AI 工具子菜单徽标）全部为空。
- 修复：`App.tsx` 启动 useEffect 增加幂等预热 `useAgentStore.getState().loadChatTools()`；
  聊天视图挂载后完整 `init()` 照旧覆盖全量（会话/模型等）。

### 邮件通知（SMTP 双通道）

- 后端：
  - 领域模型在 `crates/mosh-core/src/notify.rs`（可进 CI 单测，9 个用例）：
    `NotifySettings { system, email_enabled, email }` 持久化于 settings 键
    `notify_settings`（随多设备同步端到端加密同步）；`merge_for_save`（空授权码沿用
    已存值、port=0 按加密方式折算默认端口、开启邮件必校验）、`info_of`（回显剔除
    授权码，`has_password` 探针）。
  - 发送在 `src-tauri/src/mail.rs`：lettre `tokio1-rustls-tls`（纯 Rust TLS 栈，与
    sync/agent 同路线，规避 windows-gnu 的 OpenSSL）。加密三档：`ssl`（465 隐式
    TLS，`relay`）/ `starttls`（587 STARTTLS，`starttls_relay`）/ `none`（25 明文，
    仅内网中继）；单封 30s 超时。
  - 命令：`get_notify_settings` / `save_notify_settings` / `test_email`（表单值直发
    测试邮件，授权码空则用已存值）/ `notify_send_email`（提醒到点发送）。
- 前端：
  - 设置新增「通知」分区（`NotifySettings.tsx`，铃铛图标，位于个人资料与同步之间）：
    系统通知/邮件通知两个独立开关（可同时开）+ SMTP 表单（服务器/加密方式/端口联动
    回填/用户名/授权码 SecretInput/发件/收件）+ 保存/发送测试邮件。
  - `state/notify.ts`（zustand）：回显配置 + 保存/通道开关；`channelsOf()` 供提醒读取。
  - `state/reminder.ts`：到点 `dispatch()` 按设置分发——系统通知走插件、邮件走
    `notify_send_email`（失败仅 console 留痕不弹窗）；每轮询 tick 先 `load()` 刷新
    设置（开关后 ≤60s 生效）。
- 行为兼容：无 `notify_settings` 键时默认「系统通知开、邮件关」，与旧版一致。

验证：`npm run check` + `vite build` + `cargo test -p mosh-core`（119 用例）+
`cargo check --target x86_64-pc-windows-gnu` 全绿。

### 同步 NoSuchBucket 可读排障与桶域名容错

报错现象：手动同步失败，错误为一整段原始 XML（`GET 返回 404：<Error><Code>NoSuchBucket…`）。

- 根因：手动同步第一步 LIST 命中腾讯云 COS 的 404 NoSuchBucket——桶名漏了
  `-APPID` 后缀（控制台复制短名）、endpoint 地域与桶所在地域不一致或桶已删；
  而代码只把响应体前 300 字符原样拼进错误串，无从下手。
- 修复（`crates/mosh-core/src/sync/remote.rs`）：
  1. 新增 `s3_request_error()`：解析 S3 XML 错误体的 `<Code>`，常见码给排查提示
     （NoSuchBucket 提示 APPID 后缀/地域一致/桶存在；AccessDenied→密钥权限；
     InvalidAccessKeyId→SecretId；SignatureDoesNotMatch→SecretKey/region），
     未映射码带 `Code: Message`，非 XML 响应原样退回；`list()`/`put()`/测试连接
     同受益。
  2. 桶域名容错增强：endpoint 填了完整桶域名且首标签以「桶名-」开头（桶字段
     填短名，如 `mosh` vs `mosh-1250000000`）时直接采用该域名，不再拼出
     `mosh.mosh-125xxx.cos.…` 双重前缀（必 404）。
  3. `get()` 硬化：404 且错误码为 NoSuchBucket 时报错，不再静默当作“远端无 dump”。
  4. 设置页 Bucket 行提示注明「腾讯云 COS 需带 APPID 后缀，如 mosh-sync-1250000000」。

验证：`cargo test -p mosh-core` 120 用例（新增 `s3_error_mapping`；桶域名容错用例
更新为不双重前缀）+ `npm run check` 全绿。
