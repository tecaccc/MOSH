## 实现详情

### AI 变更后界面不刷新（BUG 修复）

| 事项 | 实现说明 |
| --- | --- |
| 根因 | `records` 仅在 App 挂载时 `loadTodos()` 一次；AI 工具（create_todo 等）在后端落库后，前端无任何刷新路径——`agent://tool` 事件只渲染工具卡片，不动应用数据。事件视图虽有各自的挂载/编辑器关闭重载，但对 AI 变更同样无感知。 |
| 数据代次（dataVersion） | `state/store.ts` 新增 `dataVersion: number` 与 `refreshData()`：重载 todos（records 响应式更新）+ 自增 dataVersion；挂载中的视图靠订阅它重载自己的事件窗口，未挂载视图靠挂载时加载。 |
| AI 工具触发刷新 | `state/agent.ts`：`agent://tool` 事件中若工具属于变更集（create_todo/create_event/update_event/delete_event/delete_events/set_todo_status/add_subtask）且执行成功，调用 `refreshData()`；刷新置于会话匹配判断之前（中途切换会话也不丢刷新）。`undoCreate` 同步改用 `refreshData()`（撤销 create_event 后日历也能刷新）。 |
| 视图接入 | `HomeView`（日程安排窗口，天气 effect 拆分避免连带重载）、`TodayView`（今日事件）、`CalendarPane`（mode/cursor 区间）的加载 effect 依赖均加入 `dataVersion`。 |

验证：`npm run check`（tsc）与 `npm run build` 均通过。

### 单实例：重复点击桌面图标不再多开（BUG 修复）

| 事项 | 实现说明 |
| --- | --- |
| 根因 | 应用无单实例锁。尤其「后台驻留」模式下窗口隐藏到托盘，再次点击桌面图标时 OS 认为应用未运行，直接启动新进程——点 N 次图标就堆 N 个后台进程（各持一份轮询/托盘/DB 连接）。
| 方案 | 接入官方 `tauri-plugin-single-instance 2.4.3`：Windows 用命名互斥体 + 隐藏窗口消息，Linux 用 DBus well-known 名（`com.mosh.app.SingleInstance`），macOS 用套接字文件。已有实例在跑时，新进程通知旧实例后立即 `exit(0)`；回调里复用既有 `show_main`（show + unminimize + set_focus）唤起旧实例主窗口。 |
| 注册位置 | `lib.rs run()`：`Builder` 拆为 `let builder` 链，插件在 `#[cfg(desktop)]` 守卫下最先注册（插件仅支持桌面端；官方要求最先注册，避免第二实例触发其他插件副作用）。无前端 API，无需改 capabilities。 |
| updater relaunch 兼容 | 核对 tauri 2.11.5 源码：`process.relaunch` 走 `request_exit` → 主循环 `RunEvent::Exit`（插件 `destroy` 先释放锁/DBus 名）→ 之后才 spawn 新进程，重启流无竞态。 |

验证：本机 glib 限制仍无法跑 Linux 目标 `cargo check`（环境预置，与改动无关），改用 `cargo check --target x86_64-pc-windows-gnu` 全量类型检查通过（含新插件）；`tauri-plugin-single-instance 2.4.3` 已入 Cargo.lock；Linux 实际多开行为待发版后验证。
