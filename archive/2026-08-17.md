## 实现详情

### AI 变更后界面不刷新（BUG 修复）

| 事项 | 实现说明 |
| --- | --- |
| 根因 | `records` 仅在 App 挂载时 `loadTodos()` 一次；AI 工具（create_todo 等）在后端落库后，前端无任何刷新路径——`agent://tool` 事件只渲染工具卡片，不动应用数据。事件视图虽有各自的挂载/编辑器关闭重载，但对 AI 变更同样无感知。 |
| 数据代次（dataVersion） | `state/store.ts` 新增 `dataVersion: number` 与 `refreshData()`：重载 todos（records 响应式更新）+ 自增 dataVersion；挂载中的视图靠订阅它重载自己的事件窗口，未挂载视图靠挂载时加载。 |
| AI 工具触发刷新 | `state/agent.ts`：`agent://tool` 事件中若工具属于变更集（create_todo/create_event/update_event/delete_event/delete_events/set_todo_status/add_subtask）且执行成功，调用 `refreshData()`；刷新置于会话匹配判断之前（中途切换会话也不丢刷新）。`undoCreate` 同步改用 `refreshData()`（撤销 create_event 后日历也能刷新）。 |
| 视图接入 | `HomeView`（日程安排窗口，天气 effect 拆分避免连带重载）、`TodayView`（今日事件）、`CalendarPane`（mode/cursor 区间）的加载 effect 依赖均加入 `dataVersion`。 |

验证：`npm run check`（tsc）与 `npm run build` 均通过。

### 待办与日程系统提醒（新增）

| 事项 | 实现说明 |
| --- | --- |
| 插件接入 | 后端 `tauri-plugin-notification = "2"`（Cargo.lock 已解析 2.3.3）+ `lib.rs` 注册 `tauri_plugin_notification::init()`；capabilities 增加 `notification:default`；前端 `@tauri-apps/plugin-notification`。 |
| 日程系统通知 | `state/reminder.ts`：既有事件提醒触发（`start - reminder_minutes ≤ now < start`）时，除应用内 Toast 外同时发系统通知「日程提醒：『{title}』将于 {时间} 开始」。 |
| 待办到期提醒 | 同一轮询内拉取 active 待办（含子任务）：到达截止时间后 60 分钟窗口内提醒一次（系统通知「待办提醒：『{title}』已到截止时间」）；错过窗口（关机/未运行）不补发，与事件提醒语义一致。 |
| 权限与降级 | `ensureNotifyPermission()` 缓存权限探测；启动时预请求（macOS 需授权，Windows/Linux 通常默认允许）；非 Tauri 环境或通知守护缺失均静默降级（应用内 Toast 仍为主通道）。 |

验证：`npm run check` 与 `npm run build` 通过；`cargo test -p mosh-core --locked` 80 项全部通过；`cargo fetch` 依赖解析正常。注：`cargo check -p mosh`（Tauri 壳）仍因本机 glib 2.68 < 2.70 无法编译（环境预置限制，与改动无关），壳层改动为单行插件注册，遵循既有模式；capabilities 权限为 `notification:default`（插件官方默认集）。
